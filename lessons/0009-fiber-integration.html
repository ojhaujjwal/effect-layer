Lesson 009 — How fibers carry context, scope, and memoization

What a fiber carries

Every fiber is a lightweight thread of execution. It runs an Effect. Crucially, every fiber carries a Context — the same typed map you learned about in lesson 001. The fiber's context is the runtime storage for:

The central function: core.withFiber

Internal Effect code accesses the current fiber via withFiber. This is how Layer.build pulls Scope and MemoMap from the runtime: 

// Source: packages/effect/src/Layer.ts:674
export const build = (self: Layer<ROut, E, RIn>) =>
  core.withFiber((fiber) =>           // ← access the current fiber
    buildWithMemoMap(
      self,
      CurrentMemoMap.getOrCreate(fiber.context),  // ← get MemoMap
      Context.getUnsafe(fiber.context, Scope.Scope)  // ← get Scope
    )
  )
Every time you call yield*, the runtime calls withFiber internally, reads the tag from the fiber's context, and returns the stored value. The fiber is the bridge between type-level declarations (Effect<A, E, R>) and runtime execution.

How Effect.provide puts services into the fiber

The complete chain, from Effect.provide(AppLayer) to yield* Logger: 

// 1. Effect.provide(AppLayer) calls scopedWith
scopedWith((scope) => {
  // 2. Build the layer — this accesses the fiber for Scope + MemoMap
  const context = Layer.buildWithScope(AppLayer, scope)  // → Context<Logger|Database|Config>

  // 3. inject the built services into the fiber's context
  provideContext(program, context)
    // internally: fiber.context = fiber.context.merge(context)
})

// 4. Now when program does:
const logger = yield* Logger
// Runtime: withFiber(fiber => fiber.context.get("app/Logger"))
// → returns { log: ..., error: ... }

Fiber + context + fork

In v4, forking always requires a Scope: Effect.forkIn(scope) or Effect.forkScoped. The child fiber inherits the parent's context, so all layered services are available: 

const program = Effect.gen(function* () {
  const db = yield* Database

  // Fork a child — it inherits the parent's context (including Database!)
  const fiber = yield* db.query("SELECT ...").pipe(
    Effect.forkScoped  // child fiber automatically added to current Scope
  )

  // Do other work concurrently...
  yield* Effect.sleep("1 second")

  // Wait for the child
  const result = yield* Fiber.join(fiber)
})
// Effect.provide(DatabaseLive) → Database is in the parent fiber's context
//   → child fiber inherits context → Database available in child too ✓
v3 users note: In v4, forkScoped and forkChild automatically provide the current Scope. The child fiber inherits the parent's context, unlike v3's fork which required explicit forkWith for context propagation. The Scope requirement on fork means forked fibers are always cleaned up.

MemoMap sharing across fibers

The MemoMap is stored in the fiber context as CurrentMemoMap. Child fibers inherit it. This means layer memoization is shared across a fiber tree: 

const parent = Effect.gen(function* () {
  // Provide a layer — builds Database once, stores it in MemoMap
  yield* program.pipe(Effect.provide(DatabaseLive))

  // Fork a child — child inherits parent's context (including MemoMap)
  yield* Effect.gen(function* () {
    yield* program.pipe(Effect.provide(DatabaseLive)) // ← uses SAME MemoMap
    // DatabaseLive is NOT rebuilt — already in the inherited MemoMap
  }).pipe(Effect.forkScoped)
})

The full picture: fiber as the runtime backbone

┌──────────────────────────────────────────────────────┐ │ FIBER │ │ │ │ ┌────────────────────────────────────────────────┐ │ │ │ FIBER CONTEXT │ │ │ │ │ │ │ │ Services Scope MemoMap Scheduler ... │ │ │ │ (yield*) (acqRel) (dedup) (timing) │ │ │ └────────────────────────────────────────────────┘ │ │ │ │ │ ┌───────────────────┼───────────────────┐ │ │ │ │ │ │ │ ▼ ▼ ▼ │ │ Layer.build Effect.gen acquireRel │ │ reads Scope, yield* reads reads Scope │ │ reads MemoMap service from ctx registers │ │ builds services from fiber ctx finalizer │ └──────────────────────────────────────────────────────┘

The fiber is not just "a user-land thread." It's the execution environment that carries all the infrastructure Layer and Effect need. When you Effect.provide, you're adding to the fiber's context. When you yield*, you're reading from it. When you fork, the child fiber gets a copy.
