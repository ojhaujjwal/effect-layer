Lesson 003 — Layer.provide, Effect.provide, and how they differ

The confusion: two different .provide calls

There are two provide operations. They have different signatures, different purposes, and work at different levels:

OperationWhat it connectsLevel
Layer.provide Layer → Layer Wiring your dependency graph
Effect.provide Layer → Effect Running your program with dependencies

Think of building a car. Layer.provide is connecting the engine to the chassis at the factory. Effect.provide is putting the key in the ignition and driving.

Layer.provide: layer feeds another layer

The mental model

You have two layers:

LoggerLive: "I can make a Logger — but I need a Config first" Layer<Logger, never, Config> ^^^^^^^^^ ^^^^^ ^^^^^^ produces no errors needs this ConfigLive: "I can make a Config — no questions asked" Layer<Config, never, never>

LoggerLive has a hole — it needs Config. ConfigLive fills that hole. 

//       hole-filler.pipe(feed into the one with the hole)
const AppLayer = LoggerLive.pipe(Layer.provide(ConfigLive))

Read it like this

Rule: A.pipe(Layer.provide(B)) means "Use B to satisfy A's dependencies."

The layer after .provide() (B) feeds the layer before it (A). B's output becomes A's input.

The type transformation step by step

// Before:
LoggerLive:  Layer<Logger,  never,  Config>
ConfigLive:  Layer<Config,  never,  never>

// LoggerLive.pipe(Layer.provide(ConfigLive))
//                  ^^^^^^^^^^^^
//        ConfigLive's output (Config) cancels out
//        LoggerLive's requirement (Config)

// After:
AppLayer:    Layer<Logger,  never,  never>
//            Logger still produced
//            Config requirement → gone (satisfied by ConfigLive)

Three-layer example

class Config extends Context.Service<Config, {
  readonly get: Effect.Effect<{ level: string }>
}>()("Config") {}
const ConfigLive = Layer.succeed(Config, {
  get: Effect.succeed({ level: "INFO" })
})

class Logger extends Context.Service<Logger, {
  readonly log: (msg: string) => Effect.Effect<void>
}>()("Logger") {}
const LoggerLive = Layer.effect(Logger,
  Effect.gen(function* () {
    const config = yield* Config
    return { log: (msg) => Effect.log(`[LOG] ${msg}`) }
  })
)

class Reporter extends Context.Service<Reporter, {
  readonly report: (err: string) => Effect.Effect<void>
}>()("Reporter") {}
const ReporterLive = Layer.effect(Reporter,
  Effect.gen(function* () {
    const logger = yield* Logger
    return { report: (err) => logger.log(`ERROR: ${err}`) }
  })
)

// Reporter needs Logger, Logger needs Config.
// Wire them: innermost dependency first, then outward.

const AppLayer = ReporterLive.pipe(
  Layer.provide(LoggerLive),   // fill LoggerLive's Config hole
  Layer.provide(ConfigLive)    // ConfigLive has no holes
)
// Type: Layer<Reporter, never, never>

// Without the middle provide, you'd get a type error:
// ReporterLive.pipe(Layer.provide(ConfigLive))
//    Error: ConfigLive doesn't satisfy ReporterLive's Logger requirement
ReporterLive needs Logger | Layer.provide(LoggerLive) v LoggerLive needs Config | Layer.provide(ConfigLive) v ConfigLive needs nothing (leaf node) Result: Layer<Reporter, never, never> All holes filled!

Effect.provide: layer feeds an effect

Once your layer has no unfilled requirements (RIn = never), you attach it to an effect to make it runnable. 

const program = Effect.gen(function* () {
  const reporter = yield* Reporter
  yield* reporter.report("disk full")
})
// Type: Effect<void, never, Reporter>
//                         "I need Reporter to run"

const runnable = program.pipe(
  Effect.provide(AppLayer)
)
// Type: Effect<void, never, never>
//                    Reporter requirement → satisfied!

Effect.runPromise(runnable)

What Effect.provide does behind the scenes

  1. Build the layer — run all generators in Layer.effect, acquire resources, etc.
  2. Add the resulting services to a context
  3. Run the program with that context — so all yield* Tag calls find their service
  4. Clean up — when the program finishes, release any scoped resources
// Approximate what Effect.provide does internally:
Effect.provide = (program, layer) =>
  Effect.gen(function* () {
    const context = yield* Layer.build(layer)    // 1. build the layer
    yield* program.pipe(                         // 3. run with that context
      core.provideContext(context)               // 2. add services to context
    )
    // 4. cleanup happens automatically via Scope
  })

Output: an Effect with fewer requirements

Used at the entry point of your application

One provide per program. Compose all your layers first (using Layer.provide), then do a single Effect.provide at the top of your application. Scattering Effect.provide calls throughout your codebase hides the dependency graph.
