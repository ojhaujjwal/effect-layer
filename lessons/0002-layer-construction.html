Layer — Constructing Services with Dependencies

Lesson 002 — Layer.succeed, Layer.effect, Layer.provide, and wiring it all together

Recall: where we left off

You know Context is a typed map from tags to services. You know how to define a tag with Context.Service and retrieve it with yield*. You know how to provide a service with Effect.provideService.

But what if a service needs another service to be built? 

class Config extends Context.Service<Config, {
  readonly get: Effect.Effect<{ level: string }>
}>()("Config") {}

class Logger extends Context.Service<Logger, {
  readonly log: (msg: string) => Effect.Effect<void>
}>()("Logger") {}

// Logger needs Config to determine log level.
// How do we build Logger given Config?

Without Layer, you'd either leak the dependency into Logger's interface (log(msg): Effect<void, never, Config>) or manually thread it through with closures. Layer is the construct that solves this.

What a Layer is

A Layer<ROut, E, RIn> is a recipe for building one or more services. Think of it as a constructor factory:

ROut — Services this layer PRODUCES
E — Error during construction
RIn — Services this layer NEEDS to be built

A mnemonic: ROEI — produces Resources, may Error, Inputs required.

Step 1: Layer.succeed — a service with no dependencies

Config doesn't depend on anything. It can just exist.

import { Context, Effect, Layer } from "effect"

class Config extends Context.Service<Config, {
  readonly get: Effect.Effect<{ level: string }>
}>()("Config") {}

//      Layer<Config, never, never>
//            ^^^^^^ ^^^^^  ^^^^^
//            Output  Error  Input (none)
const ConfigLive = Layer.succeed(Config, {
  get: Effect.succeed({ level: "INFO" })
})

Layer.succeed(tag, implementation) — the tag comes first, then a plain object implementing the Shape. No dependencies, no errors.

Step 2: Layer.effect — a service that needs dependencies

Logger needs Config to build itself. Use Layer.effect with a generator that yield*s the dependency.

class Logger extends Context.Service<Logger, {
  readonly log: (msg: string) => Effect.Effect<void>
}>()("Logger") {}

//      Layer<Logger, never, Config>
//                        ^^^^^^
//              "I need Config to build Logger"
const LoggerLive = Layer.effect(Logger,
  Effect.gen(function* () {
    const config = yield* Config  // ← pull Config from context
    return {
      log: (msg) =>
        Effect.gen(function* () {
          const { level } = yield* config.get
          console.log(`[${level}] ${msg}`)
        })
    }
  })
)

Inside Layer.effect, the generator can yield* any dependency tag. The resulting Layer type automatically records those as RIn. Here, Layer<Logger, never, Config> means: "I produce Logger, I can't fail, and I need Config."

The generator inside Layer.effect runs once when the layer is built. The closure it returns captures the dependencies. Logger's own log() method has R = never — the dependency is resolved at construction time, not call time.

Step 3: Layer.provide — satisfying a layer's dependencies

LoggerLive needs Config. Provide ConfigLive to LoggerLive.

// LoggerLive has type Layer<Logger, never, Config>
// ConfigLive has type Layer<Config, never, never>
//
// provide: feed ConfigLive into LoggerLive's Config requirement

const AppLayer = LoggerLive.pipe(
  Layer.provide(ConfigLive)
)
// Type: Layer<Logger, never, never>
//                           ^^^^^^^  Config requirement → satisfied!

Layer.provide is vertical composition: the provided layer's output becomes the consuming layer's input. The result's RIn is the provided layer's RIn (here, nothing).

Step 4: Effect.provide — wiring the layer into your program

Once your layer has all dependencies satisfied (RIn = never), provide it to your program: 

const program = Effect.gen(function* () {
  const logger = yield* Logger
  yield* logger.log("hello world")
})
// Type: Effect<void, never, Logger>

const runnable = program.pipe(
  Effect.provide(AppLayer)
)
// Type: Effect<void, never, never>  — all requirements satisfied

Effect.runPromise(runnable)
// → [INFO] hello world

The complete picture

ROut — Services this layer PRODUCES
E — Error during construction
RIn — Services this layer NEEDS to be built

Layer naming conventions (v4)

PatternMeaningExample
layerPrimary/default implementationLogger.layer
layerTestTest implementationLogger.layerTest
layerXVariant (e.g., different backend)Logger.layerSqlite

In v4 the convention is layer, not v3's Live or Default. For services without a single obvious default implementation, use descriptive suffixes.

What Layer.effect can do that Layer.succeed can't

Layer.succeedLayer.effect
Has dependenciesNo (RIn = never)Yes (yield* otherTag)
Can failNo (E = never)Yes (error channel)
Needs async setupNoYes (e.g., await connection)
Needs resource cleanupNoYes (via acquireRelease)
