Scope — The Engine Under Cleanup

Lesson 008 — How Scope tracks finalizers, and how Effect.provide/acquireRelease use it

What is a Scope?

A Scope is a lifetime boundary. You attach cleanup functions (called finalizers) to it. When the work inside the boundary is done, the Scope closes and runs every finalizer — in reverse order.

Scope = a list of cleanup functions + a lifecycle state machine ┌───────────────────────────────────┐ │ scope = Scope.make() │ │ │ │ finalizers: [] ← starts empty │ │ state: Empty │ └───────────────────────────────────┘ │ │ scope.addFinalizer(closeDb) │ scope.addFinalizer(closeFile) ▼ ┌───────────────────────────────────┐ │ finalizers: [closeFile, closeDb] │ ← LIFO: last registered, first to run │ state: Open │ └───────────────────────────────────┘ │ │ scope.close(exit) ▼ ┌───────────────────────────────────┐ │ Run closeFile(exit) │ │ Run closeDb(exit) │ │ state: Closed │ └───────────────────────────────────┘

The three states

Empty — no finalizers yet → add finalizer → Open — accepting finalizers → close → Closed — finalizers ran

Once closed, a Scope rejects new finalizers. Closing an empty Scope is a no-op. The exit value passed to close tells finalizers whether the work succeeded, failed, or was interrupted.

Manual Scope usage (the low-level API)

import { Effect, Exit, Scope } from "effect"

const program = Effect.gen(function* () {
  const scope = yield* Scope.make()     // create a Closeable scope

  yield* Scope.addFinalizer(scope,      // register cleanup
    Effect.log("cleanup 1"))

  yield* Scope.addFinalizer(scope,      // register more cleanup
    Effect.log("cleanup 2"))

  yield* Effect.log("doing work...")

  yield* Scope.close(scope, Exit.void)  // close — runs finalizers in LIFO
})
// Logs:
//   doing work...
//   cleanup 2     ← last registered, first run
//   cleanup 1     ← first registered, last run

But you rarely use Scope manually. Three higher-level APIs handle the lifecycle for you:

API #1: Effect.scoped

Effect.scoped(effect) wraps an effect in a Scope, then closes it automatically when the effect finishes: 

Effect.scoped(                // create Scope → provide it → run → close
  Effect.gen(function* () {
    const conn = yield* Effect.acquireRelease(
      connectToDb(),        // acquire
      (conn) => conn.close() // release: auto-registered on the scope
    )
    yield* conn.query("SELECT 1")
    // ... Scope closes here automatically, conn.close() runs
  })
)
// Type: Effect<A, E, Exclude<R, Scope>>
//                           ^^^^^^^^  Scope requirement satisfied!
Mental model: Effect.scoped pushes the "open bracket" { and the "close with cleanup bracket" } around an effect, automatically. You focus on the middle.

API #2: Effect.acquireRelease

acquireRelease is the try/finally of Effect. It returns an Effect that requires Scope, because the release function must be registered somewhere: 

Effect.acquireRelease(
  acquire: Effect<A, E, R>,
  release: (resource: A, exit: Exit) => Effect<unknown>
): Effect<A, E, R | Scope>
//                     ^^^^^  "I need a Scope to register my cleanup"

Internally, acquireRelease does this: 

// Simplified implementation:
acquireRelease = (acquire, release) =>
  Effect.flatMap(Scope.Scope, (scope) => {  // ← gets Scope from fiber context
    return Effect.uninterruptibleMask(
      (restore) =>
        Effect.flatMap(restore(acquire), (resource) =>
          Effect.zipRight(
            Scope.addFinalizerExit(scope, (exit) =>
              release(resource, exit)     // ← register release as a finalizer
            ),
            Effect.succeed(resource)
          )
        )
    )
  })

Notice: acquireRelease uses yield* Scope.Scope internally. It gets the current Scope from the fiber context. This is how the finalizers end up on the right Scope — whatever Scope is active in the fiber at the time acquireRelease runs.

API #3: scopedWith (the engine inside Effect.provide)

scopedWith is the function that Effect.provide and Effect.scoped both call internally. It creates a Scope, calls your callback with it, then uses onExit to close it when done: 

// Source: internal/effect.ts
const scopedWith = (f: (scope: Scope) => Effect<A, E, R>) =>
  suspend(() => {
    const scope = scopeMakeUnsafe()         // 1. create scope
    return onExit(                          // 3. register cleanup hook
      f(scope),                             // 2. run the effect with this scope
      (exit) =>
        scopeCloseUnsafe(scope, exit)       // 4. when done → close scope
    )
  })

onExit guarantees the Scope closes even if the effect fails or is interrupted. There is no code path where the Scope is left open.

How everything connects

Effect.provide(layer) │ ├── scopedWith((scope) => ← creates + auto-closes Scope │ │ │ ├── Layer.buildWithScope(layer, scope) │ │ │ │ │ └── Layer.effect runs generator │ │ │ │ │ ├── acquireRelease(connect, close) │ │ │ │ │ │ │ └── registers close() on <scope> │ │ │ │ │ └── returns { query, ... } │ │ │ ├── context (built services) │ │ │ └── provideContext(program, context) │ │ │ └── runs your program (DB pool is alive) │ └── onExit → scopeCloseUnsafe(scope, exit) │ └── runs pool.end() → DB connection closed ✓

Where the Scope lives (v4)

In v4, Scope is a Context.Reference — a service with a default value. The fiber runtime creates a default Scope at startup and stores it in the fiber's context. This means any effect that needs Scope can access it without you providing it explicitly: 

// Scope.Scope is a Context.Reference with a default value
// It's always available in the fiber context
// That's why acquireRelease works anywhere —
//   yield* Scope.Scope always returns a scope

// But scopedWith creates a NEW scope that overrides the default:
//   Inner acquireRelease calls register on the inner scope
//   When inner scope closes, only inner finalizers run
//   The outer (default) scope is unaffected

Scope.provide (v4 rename from Scope.extend in v3)

Scope.provide(scope)(effect) makes a specific Scope available to an effect, removing Scope from the effect's requirements: 

const effectThatNeedsScope: Effect<void, never, Scope> = ...

const withoutScopeRequirement = effectThatNeedsScope.pipe(
  Scope.provide(myScope)   // or: myScope.pipe(Scope.provide(effect))
)
// Type: Effect<void, never, never>

This is useful when you create a Scope manually and want an effect to use it (registering finalizers on your Scope), without wrapping in a new one.
