merge & provideMerge — Horizontal Composition

Lesson 004 — Merging independent layers and passing dependencies through

Two kinds of composition

So far you've seen vertical composition: one layer feeds another's dependencies. But what if two layers are independent (neither needs the other)? You need to combine them side by side.

Vertical (provide): Horizontal (merge): A (needs B) A (independent) B (independent) │ │ │ │ Layer.provide(B) └──────┬─────────┘ ▼ │ A' (B satisfied) Layer.merge │ ▼ A + B together

Layer.merge: combine independent layers

Two services that don't depend on each other — but your program needs both. Layer.merge bundles them into one layer. 

class Config extends Context.Service<Config, {
  readonly get: Effect.Effect<{ level: string }>
}>()("Config") {}
const ConfigLive = Layer.succeed(Config, {
  get: Effect.succeed({ level: "INFO" })
})
// Layer<Config, never, never>

class Metrics extends Context.Service<Metrics, {
  readonly track: (event: string) => Effect.Effect<void>
}>()("Metrics") {}
const MetricsLive = Layer.succeed(Metrics, {
  track: (event) => Effect.log(`[METRICS] ${event}`)
})
// Layer<Metrics, never, never>

// Both are leaf nodes — no dependencies — combine them:
const Infrastructure = ConfigLive.pipe(
  Layer.merge(MetricsLive)
)
// Layer<Config | Metrics, never, never>
//          ^^^^^^^^^^^
//    Both services in the output!

What merge does to the types

ConfigLive:   Layer<Config,  never, never>
MetricsLive:  Layer<Metrics, never, never>
                       │          │
                       └─ merge ──┘
                            │
                            ▼
              Layer<Config | Metrics, never, never>
              //      ^^^^^^  ^^^^^^^  union of outputs
Key: merge is horizontal. Both outputs appear in the result. Both layers are built concurrently (in parallel), not sequentially. Neither knows about the other.

The four composition operations compared

OperationDirectionOutput containsUse for
merge Horizontal Both layers' services Combining independent leaf services
provide Vertical Only the consumer's services Hiding implementation details
provideMerge Vertical Both: consumer + dependency Test stacks, shared dependencies

Layer.provideMerge: provide AND keep the dependency

provide hides the dependency from the output. But sometimes you want the dependency to remain visible — especially when building test stacks where multiple downstream layers share the same upstream.

Layer.provide 
provides Logger
satisfies Config

Logger   ← hides Config
 ▼
visible
Layer.provideMerge 
provides Logger AND Config
satisfies Config

Logger + Config
  ▼         ▼
both visible

// LoggerLive: Layer<Logger, never, Config>
// ConfigLive: Layer<Config, never, never>

// provide: Config is consumed and hidden
LoggerLive.pipe(Layer.provide(ConfigLive))
// Layer<Logger, never, never>
//        ^^^^^^  Config gone from output

// provideMerge: Config is consumed AND passed through
LoggerLive.pipe(Layer.provideMerge(ConfigLive))
// Layer<Logger | Config, never, never>
//        ^^^^^^^^^^^^^^  Both in output!

When provideMerge matters

A test stack where a database is shared by multiple services: 

class Database extends Context.Service<Database, {
  readonly query: (sql: string) => Effect.Effect<unknown[]>
}>()("Database") {}

class UserRepo extends Context.Service<UserRepo, {
  readonly getById: (id: string) => Effect.Effect<unknown>
}>()("UserRepo") {}

class OrderRepo extends Context.Service<OrderRepo, {
  readonly getById: (id: string) => Effect.Effect<unknown>
}>()("OrderRepo") {}

// UserRepo needs Database, OrderRepo also needs Database.
// Both must share the SAME Database instance.

const TestLayers = Layer.merge(
  UserRepoLive.pipe(Layer.provideMerge(DatabaseLive)),
  OrderRepoLive.pipe(Layer.provideMerge(DatabaseLive))
)
// Layer<UserRepo | OrderRepo | Database, never, never>

// Without provideMerge, Database would vanish after the first provide,
// and the second repo couldn't see it. With provideMerge, Database
// is visible to the merge, so the layer memoizer shares it.
Why this works: Because of layer memoization — the same layer instance (DatabaseLive) is built only once. Even though it appears in two provideMerge calls, the MemoMap deduplicates it. Both repos get the same database connection.
